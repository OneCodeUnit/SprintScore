# SprintScore

Веб-приложение для оценки спринта командой: участники ставят оценку от 1 до 10,
ведущий завершает голосование и показывает всем среднюю оценку и распределение голосов.

## Как это работает

**Участник** — страница `/`:

1. Нажимает на карточку с оценкой (1–4 красные, 5–7 жёлтые, 8–10 зелёные).
2. Нажимает **«Подтвердить»** — голос уходит на сервер, счётчик проголосовавших растёт у всех.
3. Пока ведущий не завершил голосование, можно нажать **«Голосовать заново»** и выбрать другую оценку.

Всё время видно, сколько человек на странице и сколько из них уже проголосовало.
Чужие оценки до завершения голосования не видны — их нет даже в сетевом трафике.

**Ведущий** — страница `/admin`:

- **«Завершить голосование»** — раскрывает результаты всем: среднюю оценку и число голосов за каждую оценку.
- **«Заново»** — сбрасывает голоса и открывает новый раунд.

Аутентификации нет: ведущим становится любой, кто открыл `/admin`.
Ведущий учитывается в числе участников онлайн и может ввести свою оценку в скрытое поле.
Корректная оценка учитывается в голосовании; её можно очистить до завершения раунда.

## Быстрый старт в Docker

Готовые образы публикуются только при публикации GitHub Release. Образ получает
тег релиза (например `1.0`) и `sha-*`. Тег `latest` указывает на последний
стабильный релиз; предварительные релизы его не обновляют.

Чтобы восстановить образ существующего релиза, откройте Actions → Build and publish
image → Run workflow, выберите ветку `master` и укажите тег в `release_tag` (например
`1.1`). Workflow проверит, что релиз опубликован, и соберёт код его тега.

Создайте файл `docker-compose.yml`:

```yaml
services:
  sprintscore:
    image: ghcr.io/onecodeunit/sprintscore:latest
    container_name: sprintscore
    restart: unless-stopped
    ports:
      - "8080:8080"
```

и поднимите:

```bash
docker compose up -d
```

Можно открыть:

- `http://localhost:8080` — страница участника;
- `http://localhost:8080/admin` — страница ведущего.

Чтобы подключилась команда, раздайте коллегам адрес машины в локальной сети. Порт 8080 при этом должен быть открыт.

### Собрать образ из исходников

```bash
git clone https://github.com/OneCodeUnit/SprintScore.git
cd SprintScore
docker compose up -d --build
```

Корневой compose содержит `build: .` и публикует порт 8080. Серверный вариант для
существующего Caddy находится в `deploy/`: скачайте оттуда compose и `.env.example`,
сохраните образец как `.env` и задайте имя сети Caddy. Если вы уже запускаете сервис
из клона репозитория за Caddy, используйте этот серверный compose вместо корневого.

Теги всех сборок видны на странице пакета:
[Packages → sprintscore](https://github.com/OneCodeUnit/SprintScore/pkgs/container/sprintscore).

Внутри контейнера приложение всегда слушает HTTP на порту 8080 и работает не от root.
HTTPS образ не терминирует: чтобы открыть сервис в интернет, поставьте перед ним
обратный прокси.

### О чём помнить

- Голоса лежат в памяти процесса, поэтому **перезапуск контейнера обнуляет голосование**.
- По той же причине должен работать **ровно один экземпляр**: несколько реплик разъедутся
  по состоянию, а SignalR без backplane не свяжет их между собой.
- Здоровье — `GET /healthz`. В образе настроен `HEALTHCHECK`, поэтому `docker compose ps`
  показывает реальное состояние приложения, а не только то, что процесс запущен.
- Образ собран под `linux/amd64`. На Apple Silicon и других ARM-машинах Docker запустит
  его через эмуляцию — работать будет, но медленнее и с предупреждением; на ARM-сервере
  без настроенного binfmt он не стартует. В этом случае соберите образ из исходников.
## Запуск из исходников

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0).

```bash
dotnet run --project src/SprintScore
```

Приложение поднимется на `http://localhost:5218` (профиль `http` из `Properties/launchSettings.json`).

Тесты:

```bash
dotnet test
```

Клиентские регрессионные тесты (нужен Node.js):

```bash
node --test tests/client/*.test.cjs
```

## Стек

- ASP.NET Core 10, Razor Pages
- SignalR — синхронизация в реальном времени
- Состояние — in-memory, без базы данных (перезапуск приложения сбрасывает голосование)
- Фронтенд — обычные JS и CSS, без сборки и npm

## Устройство

| Файл | Назначение |
| --- | --- |
| `src/SprintScore/Voting/VotingSession.cs` | Состояние сессии: соединения, голоса, раунды. Единственный источник правды |
| `src/SprintScore/Voting/VotingHub.cs` | SignalR-хаб: `Vote`, `RetractVote`, `Reveal`, `Restart` |
| `src/SprintScore/Voting/PresenceSweeper.cs` | Убирает участников, которые закрыли страницу и не вернулись |
| `src/SprintScore/wwwroot/js/app.js` | Клиент обеих страниц |
| `tests/SprintScore.Tests/VotingSessionTests.cs` | Тесты логики голосования |

Участник опознаётся по идентификатору из `localStorage`, поэтому перезагрузка страницы
не теряет голос, а несколько вкладок одного человека считаются за одного участника.
При обнаружении отключения участник перестаёт считаться онлайн. Его голос сохраняется
ещё 20 секунд на случай перезагрузки страницы; после завершения голосования результаты
сохраняются независимо от отключений.
